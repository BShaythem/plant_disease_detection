# GAINAfrica — Olive disease detection

Mobile app (React Native) for photo-based olive disease diagnosis, with
a grounded chat assistant (RAG), running entirely on-device — no
server, no network dependency at inference time.

## Tech stack

| Component | Choice |
|---|---|
| App | React Native (Expo, TypeScript) |
| Vision (classification) | MobileNetV4-conv-small, ONNX, via `onnxruntime-react-native` |
| LLM (generation) | Quantized SLM (GGUF), via `llama.rn` |
| Embeddings (RAG) | via `llama.rn` (embedding mode) or ONNX fallback |
| Knowledge base | SQLite (`knowledge.db`), built offline in Python |
| User data | SQLite (`app.db`), created and migrated on-device |
| Chat UI | `react-native-gifted-chat` |

See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for the full
pipeline and [`docs/SCHEMA.md`](docs/SCHEMA.md) for both database
schemas.

## Repo structure

```
gainafrica/
├── app/              # React Native (Expo) application
├── ml/               # Python workspace — builds knowledge.db, benchmarks
├── knowledge/         # Content (disease cards, RAG corpus) — Markdown
├── models/            # Model weights (gitignored, see SETUP_AI.md)
├── docs/               # Project documentation
└── scripts/            # Shared scripts (model download, etc.)
```

## Prerequisites

- Git
- Node.js 20 LTS (nvm use 20) (see `.nvmrc`)
- Python 3.11 (not 3.13 — missing wheels for some ML packages)
- Android Studio (with SDK 34+ and an emulator) or Xcode (if on macOS) or A physical Android/iOS device with enough ram (Expo Go does NOT work here — native ML modules required)

## Quick start

### 1. Clone and configure

```bash
git clone <repo-url> gainafrica
cd gainafrica
cp .env.example .env   # then fill in the required values
```

### 2. Python environment (`ml/`)

```bash
cd ml
python3.11 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Fetch the models

```bash
# Linux / macOS / Git Bash:
bash scripts/fetch_models.sh

# Windows (PowerShell):
.\scripts\fetch_models.ps1
```

See [`docs/SETUP_AI.md`](docs/SETUP_AI.md) for details — weights are
never committed to git.

### 4. Build the knowledge base

```bash
cd ml
python scripts/build_knowledge_db.py
```

Generates `ml/build/knowledge.db`. Re-run it any time a disease card or
corpus document under `knowledge/` changes.

### 5. Run the app

```bash
cd app
npm install
npx expo prebuild
npx expo run:android   # or run:ios
```

## Useful scripts

| Command | What it does |
|---|---|
| `python ml/scripts/build_knowledge_db.py` | Rebuilds `knowledge.db` from `knowledge/` |
| `bash scripts/fetch_models.sh` (or `.\scripts\fetch_models.ps1`) | Downloads required models into `models/` |
| `npx expo run:android` / `run:ios` | Builds and runs a dev client on the connected device |

## Important conventions

- **Never commit** model files (`.gguf`, `.onnx`, `.onnx_data`) or
  compiled `.db` files — all gitignored; only the `.sql`/scripts that
  generate them are versioned.
- **Never edit a migration that has already run** against `app.db` —
  always append a new one. See `docs/SCHEMA.md`.
- `app/android/` and `app/ios/` are gitignored (regenerated by `expo
  prebuild`) — don't commit them, guaranteed merge-conflict source with
  three people.
